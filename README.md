# Постобработка OCR паспорта РФ

## Кратко

Решение принимает документ только тогда, когда все обязательные проверки проходят одновременно. При любом сомнении документ отклоняется. Основной приоритет — не допустить ошибочного принятия, поскольку по условиям задания цена такого события существенно выше цены отклонения.

- **Python:** 3.10+ (используются только стандартные модули Python).
- **Вычислительные ресурсы:** CPU; GPU не требуется.
- **Интернет:** не требуется; скрипт не обращается к сетевым ресурсам.
- **Внешние зависимости:** отсутствуют.
- **Дата проверки действительности паспорта:** `01.10.2026`.

## Запуск

Из корня проекта:

```bash
python3 postprocess.py data/test_predictions.jsonl answers.jsonl
```

Команда перезаписывает `answers.jsonl`. Чтобы проверить обучающую выборку, можно запустить:

```bash
python3 postprocess.py data/train_predictions.jsonl /tmp/answers_train.jsonl
python3 evaluate.py /tmp/answers_train.jsonl data/train_labels.jsonl
```

## Формат результата

Каждая строка выходного JSONL — отдельный JSON-объект с `doc_id` и решением `accept` или `reject`. Поле `fields` присутствует только для принятых документов и содержит все 10 полей, требуемых заданием.

Пример отклонения:

```json
{"doc_id":"te_00001","decision":"reject"}
```

Пример принятия (значения условные):

```json
{"doc_id":"example","decision":"accept","fields":{"Last_name_ru":"ИВАНОВ","First_name_ru":"ИВАН","Middle_name_ru":"ИВАНОВИЧ","Sex_ru":"МУЖ.","Birth_date":"01.01.1990","Birth_place_ru":"МОСКВА","Issue_date":"01.01.2010","Issue_organisation_code":"770-001","Licence_number":"45 10 123456","Issue_organization_ru":"ОТДЕЛОМ УФМС РОССИИ ПО Г. МОСКВЕ"}}
```

## Логика принятия

Для принятия документ должен пройти все проверки:

1. Все 10 полей присутствуют и имеют достаточную общую и посимвольную уверенность OCR.
2. Значения проходят проверки структуры и формата: даты, пол, код подразделения, номер паспорта, ФИО и длины текстовых полей.
3. Даты календарно корректны, дата выдачи не позже контрольной даты, а паспорт считается действительным на `01.10.2026` по реализованным правилам возрастной замены.
4. Код подразделения найден в локальном справочнике.
5. MRZ проходит проверки контрольных цифр номера и даты рождения; даты, пол, номер и код согласуются с визуальной зоной.
6. Фамилия и имя согласуются с MRZ после ограниченной нормализации распространённых OCR-подмен.
7. Текстовые поля места рождения и органа выдачи проходят проверки геометрии, а наименование органа выдачи достаточно похоже на вариант из локального справочника для указанного кода.

Никакие значения не исправляются догадками: если проверка не проходит, документ отклоняется.

## Результаты проверки

Повторный запуск текущего `postprocess.py` на предоставленных данных дал:

| Выборка | Всего | Принято | Отклонено | Принято с ошибкой по `evaluate.py` |
|---|---:|---:|---:|---:|
| Train | 3000 | 96 (3,2%) | 2904 | 0 |
| Test | 2000 | 75 (3,75%) | 1925 | Неизвестно без разметки |

Для train команда `evaluate.py` подтвердила 96 верных принятий и 0 принятий с ошибкой. Для test разметки нет, поэтому ноль ошибок не является проверенным фактом. Рабочий прогноз — 75 принятых документов, ожидаемое количество ошибочных принятий — 0; это прогноз, а не гарантия.

**Ограничение:** доля принятых низкая. Это консервативный вариант с приоритетом точности, а не доказательство максимальной полноты. Ослаблять пороги следует только после калибровки на отдельной размеченной выборке.
